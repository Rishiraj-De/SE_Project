01 Executive Overview & Project Philosophy

"Understand existing software before changing it." In enterprise software engineering, between 60% and 80% of total lifecycle costs are expended on software maintenance, legacy onboarding, refactoring, and bug investigations. When senior engineers inherit multi-year repositories, they face steep cognitive hurdles: missing documentation, undocumented circular dependencies, hidden blast radiuses, volatile files (churn hotspots), and stale dead code.

Unlike generic AI tools that hallucinate high-level summaries without grounding, Digital Archaeologist provides a deterministic, AST-driven forensic platform. It reconstructs architectural topologies, measures cyclomatic complexity and Git churn velocity, detects dependency cycles via directed graph algorithms, and calculates transitive blast radiuses before a single line of code is edited.

Deterministic AST Engine

Multi-language parser extracting classes, methods, imports, and branch complexity without running unreliable test runners.

Transitive Blast Radius

Calculates upstream and downstream dependency ripple effects, SQL write impacts, and third-party gateway vulnerabilities.

Grounded AI Explanations

Contextual AI assistant that accompanies every answer with verified file paths, line numbers, snippets, and Git commit hashes.

03 Deep Dive: Python AST & Forensic Engine (analyzer.py)

The core analysis engine located at analysis-engine/analyzer.py is a lightweight, zero-dependency Python script designed for maximum execution speed across heterogeneous codebases (TypeScript, JavaScript, Python, Java, Go, Rust).

1. Cyclomatic Complexity Calculation

Computes the number of linearly independent paths through program source code using McCabe's formulation based on decision points: 

# Decision patterns extracted by regex:
patterns = [
    r'\bif\b', r'\belse\s+if\b', r'\belif\b', r'\bfor\b', r'\bwhile\b',
    r'\bcase\b', r'\bcatch\b', r'\bexcept\b', r'\b\?\s*[^:]+:', r'&&', r'\|\|'
]
complexity = 1 + sum(len(re.findall(p, content)) for p in patterns)

2. Directed Adjacency Graph & DFS Cycle Detection

Constructs both forward adjacency (adjacency[u] → v, meaning u depends on v) and reverse adjacency (rev_adjacency[v] → u, meaning u is a dependent of v). Circular dependencies are isolated via Depth-First Search with a three-color recursion stack:

  • 0 (Unvisited): Node has not been touched.
  • 1 (Visiting): Node is on the active traversal path. If an adjacent node has state 1, a circular dependency cycle is detected.
  • 2 (Visited): Node and all reachable subtrees are completely analyzed.

3. Git Forensics & Churn Dynamics

Extracts repository commit history and file volatility using direct Git CLI bindings: git log --pretty=format:%h|%an|%ad|%s and git log --name-only. Files with high historical modification frequency are flagged as high-churn candidates.

4. Mathematical Composite Health Score

The overall Engineering Health Index (0–100) is synthesized using a multi-factor weighted equation: 

Health Score = round(
    (ArchitectureScore * 0.25) +
    (MaintainabilityScore * 0.25) +
    (TestCoverageScore * 0.20) +
    (DependencyHealthScore * 0.20) +
    (DocumentationScore * 0.10)
)
Where:
- ArchitectureScore = max(20, 100 - (circular_count * 15) - (high_coupling_modules * 5))
- MaintainabilityScore = max(20, round(100 - (avg_cyclomatic_complexity * 3)))
- TestCoverageScore = min(100, round((test_files / total_files) * 300))
- DocumentationScore = min(100, round(20 + (doc_files * 15)))
- DependencyHealthScore = max(20, 100 - (technical_debt_items * 4))

05 Static Blast Radius & Transitive Impact Analysis

Implemented in backend/src/services/impact.service.ts, this subsystem solves the classic developer dilemma: "If I modify function X, what breaks across the rest of the application?"

Downstream & Upstream Traversal

Traverses the reverse adjacency graph to discover direct and transitive callers. If PaymentService.processPayment() is modified, the service discovers that CheckoutController, TransactionService, and NotificationService are impacted.

Side-Effect & Infrastructure Risk

Scans call paths for database write operations (e.g., DatabaseConnector.executeWrite()) and external third-party gateway interactions (Stripe, PayPal, banking APIs) to establish risk ratings (CRITICAL, HIGH, MEDIUM, LOW).

Impact Output Schema

interface BlastRadiusResult {
  targetSymbol: string;
  targetFile: string;
  affectedModules: string[];
  affectedFunctions: string[];
  databaseOperations: number;
  externalApis: number;
  riskRating: "CRITICAL" | "HIGH" | "MEDIUM" | "LOW";
  confidence: "High (Static AST)" | "Requires Verification";
  callHierarchy: {
    name: string;
    type: "root" | "caller" | "dependency";
    file: string;
    children: CallNode[];
  };
  reasoning: string[];
}

06 Relational Database Schema (Prisma / SQLite)

The persistent database model defined in backend/prisma/schema.prisma incorporates 15 normalized tables ensuring comprehensive auditability:

Model Primary Attributes Relationships & Cascade Rules
Repository id, name, url, defaultBranch, ownerId 1-to-many with AnalysisRun, Contributor, Commit, Documentation, AISession.
AnalysisRun id, branch, commitHash, status, healthScore, archScore Belongs to Repository (Cascade). 1-to-many with File, Dependency, TechDebt, RiskScore.
File id, path, name, extension, language, loc, complexity Belongs to AnalysisRun. 1-to-many with ClassDefinition, FunctionDefinition, Dependencies.
Dependency id, fromFileId, toFileId, importStatement, isCircular Relates source file to target file. Supports graph reconstruction and coupling queries.
TechnicalDebt id, severity, component, file, issue, category, recommendation Structured audit log tracking complexity hotspots, dead code, and security alerts.
RiskScore id, fileId, complexity, changeFrequency, riskScore, riskLevel Synthesizes Git commit frequency with cyclomatic complexity.
Commit id, hash, author, message, timestamp, linesAdded, linesDeleted Stores full historical repository commits and file churn changes.
